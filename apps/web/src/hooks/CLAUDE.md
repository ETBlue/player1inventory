# Custom Hooks

**Navigation:**
- `useAppNavigation()` (`src/hooks/useAppNavigation.ts`) - Tracks navigation history in sessionStorage, provides `goBack()` function for smart back navigation to previous app page (fallback to home). Uses `router.history.push(previousUrl)` to preserve full URL (including search params) when going back.
- `useNavigationTracker()` (`src/hooks/useNavigationTracker.ts`) - Global hook (used in `__root.tsx`) that records every page visit as a full URL (`pathname + searchStr`) in sessionStorage. When params change on the same page, updates the last entry in place rather than appending a new one.

**Item List State:**
- `useUrlSearchAndFilters()` (`src/hooks/useUrlSearchAndFilters.ts`) - Manages search query, tag filter state, vendor/recipe filter state, and UI visibility (filters panel, tags visible) via URL params (`?q=`, `?f_<typeId>=`, `?f_vendor=id1,id2`, `?f_recipe=id1,id2`, `?filters=1`, `?tags=1`). Uses `router.history.replace` to update params in place (same history entry). Note: `filterState` only contains tag type filters — `vendor` and `recipe` keys are reserved and excluded from `filterState`. Exposes `selectedVendorIds: string[]`, `selectedRecipeIds: string[]`, `toggleVendorId(id)`, `toggleRecipeId(id)`, `clearVendorIds()`, `clearRecipeIds()`.
- `useSortFilter(storageKey)` (`src/hooks/useSortFilter.ts`) - Manages sort field and direction via localStorage key `${storageKey}-sort-prefs`. Used by all item list pages for per-page sort persistence. Accepts optional `defaultSortBy` option (defaults to `'name'`).
- `useScrollRestoration(key, scrollRef)` (`src/hooks/useScrollRestoration.ts`) - Saves/restores the scroll position of a scroll container element for a given key (typically the full URL). The app shell pins `<main>` to the viewport so the window never scrolls — list views scroll inside an inner `overflow-y-auto` container, so the hook operates on `scrollRef.current.scrollTop` / `.scrollTo`, not `window`. Saves scroll on component unmount (SPA navigation away); restores after data loads. Usage: attach a `useRef<HTMLDivElement>(null)` to the scroll container, call with `currentUrl` from `useRouterState` + the ref, then call `restoreScroll()` in a `useEffect` conditioned on `!isLoading`. For the 4 detail-page Items tabs (tags/vendors/recipes/shelves) the scroll container is owned by `LayoutInnerPages` and shared via `<Outlet>`; those callers read the ref from `useInnerPageScrollRef()` (a context exposed by `LayoutInnerPages`).

**Data Utilities:**
- `useVendorItemCounts()` (`src/hooks/useVendorItemCounts.ts`) - Returns `Map<vendorId, number>` of item counts per vendor, memoized with useMemo for performance
- `useItemSortData(items)` (`src/hooks/useItemSortData.ts`) - Returns `{ quantities, expiryDates, purchaseDates }` for sort operations on item lists. `quantities` is a `useMemo` (synchronous, no race condition). Local mode: `expiryDates` and `purchaseDates` are TanStack Query queries under the `['sort', ...]` key namespace. Cloud mode: uses `useLastPurchaseDatesQuery` (Apollo batch query) and derives expiry dates synchronously — no TanStack Query involved. Used by all five item list pages. Checkout explicitly invalidates `['sort', 'purchaseDates']` after purchase (local mode).
- `useItemLogs(itemId)` (`src/hooks/useInventoryLogs.ts`) - Returns inventory log entries for an item. Dual-mode: local uses TanStack Query + Dexie; cloud uses `useItemLogsQuery` (Apollo).
- `useAddInventoryLog()` (`src/hooks/useInventoryLogs.ts`) - Mutation hook to add an inventory log entry. Dual-mode: local calls `addInventoryLog` with the active location's id threaded in (matches the read side, `useItemLogs`, which filters by `activeLocationId`); cloud calls `useAddInventoryLogMutation` (Apollo).
- `useConsumeRecipes()` (`src/hooks/useRecipes.ts`) - Batch mutation hook for cooking done. Sends all item quantity updates, inventory logs, and recipe `lastCookedAt` stamps in a single call. Dual-mode: local uses `consumeRecipesBatch` (Dexie transaction); cloud calls `useConsumeRecipesMutation` (Apollo). Used exclusively by the cooking page `handleConfirmDone`.

**Shopping:**
- `useVendorCartCounts()` (`src/hooks/useVendorCartCounts.ts`) - Returns `Map<vendorId, { count: number; inactiveCount: number }>` for the `/shopping` index cards + the `'count'` sort. `count` is items with this vendor stocked in the **active location** (cloud: global, no location gate); `inactiveCount` is the subset with `targetQuantity === 0` (cloud: always 0). Distinct from `useVendorItemCounts()` below, which stays global/location-unaware for `/settings/vendors` — vendor management is location-independent, so the two pages showing different counts for the same vendor is expected, not a bug (see `apps/web/src/routes/CLAUDE.md`).
- `useVendorCart(vendorId: string | null)` (`src/hooks/useShoppingCart.ts`) - Gets the active cart for a specific vendor (null = "No vendor" cart). Local: TanStack Query keyed `['cart', 'vendor', vendorId]`; `getCart` is a pure read — carts are bootstrapped up front by `ActiveLocationProvider` (see `useActiveLocation()` below), not created lazily here. Cloud fallback: single active cart.
- `useAllActiveCarts()` (`src/hooks/useShoppingCart.ts`) - Returns all active carts (one per vendor). Local: TanStack Query keyed `['cart', 'all-active']`. Cloud fallback: single cart wrapped in array.
- `useLastPurchasedByVendor()` (`src/hooks/useShoppingCart.ts`) - Returns a `Map<vendorId, Date | null>` of the most recent `completedAt` per vendor, derived from completed carts. Local mode only (cloud returns empty map; server-side sort deferred). Query key `['cart', 'last-purchased-by-vendor']`. Drives the `'recent'` sort on the shopping index.

**Cloud / Auth:**
- `usePostLoginMigration()` (`src/hooks/usePostLoginMigration.ts`) - Cloud mode only. Detects when a signed-in user has local IndexedDB items and has not been prompted before (localStorage `migration-prompted` key). Exposes `state: MigrationState`, `dismiss()`, and `importData(conflictResolution)`. `importData` calls `fetchLocalPayload()` then `importCloudData()` to migrate local data to cloud. Used by `PostLoginMigrationDialog`.

**Location:**
- `useLocations()` (`src/hooks/useLocations.ts`) - Returns all locations. Local-first only (no cloud GraphQL backend yet) — mode-independent. Also exposes `useCreateLocation`, `useUpdateLocation`, `useDeleteLocation`, `useReorderLocations`.
- `useActiveLocation()` (`src/hooks/useActiveLocation.tsx`) - React Context hook exposing `{ activeLocationId, setActiveLocationId, activeLocation }`. The active id is persisted in localStorage under `active-location-id` (`ACTIVE_LOCATION_STORAGE_KEY`), defaults to `DEFAULT_LOCATION_ID` (`'local'`), and falls back to the default if the stored id no longer matches any location (e.g. it was deleted). The provider `ActiveLocationProvider` is mounted in `__root.tsx` (wraps the whole app) and reads the location list via `useLocations`. It also bootstraps shopping carts: whenever `activeLocationId` changes (local mode only), it calls `bootstrapCarts(activeLocationId)` to ensure the no-vendor + per-vendor carts exist for that location, then invalidates `['cart']` queries so any cart query that resolved before the bootstrap finished refetches. This keeps `getCart` a pure read (see `db/operations.ts`) instead of lazily creating carts inside a `queryFn`. **LIVE (PR D):** the active location now scopes all stock-bearing data. Every data hook that reads/writes stock threads `activeLocationId` down to the operations layer (it appears in TanStack Query keys so switching the active location refetches): `useItems`/`useItem` (return a **joined `PantryItem`** = global `Item` + active-location `ItemStock` fields), `useLastPurchaseDate`, `useItemSortData`, `useItemLogs`, the cart hooks (`useActiveCart`/`useVendorCart`/`useAllActiveCarts`/`useLastPurchasedByVendor` — carts are per `location × vendor`), `useCreateItem`/`useUpdateItem` (split the per-location stock STATE into the active-location `ItemStock`; the global stock configuration stays on the `Item` — see the v16 note in `db/CLAUDE.md`), `useConsumeRecipes` (cooking), and `useCreateVendor` (pre-creates the vendor cart for the active location). When no `ActiveLocationProvider` is mounted (isolated unit/story renders), the hook returns a fallback pinned to `DEFAULT_LOCATION_ID` with a no-op setter, so tests don't need to wrap in a provider.
- `useStockedItems()` (`src/hooks/useItems.ts`) - Returns the **pantry's** data source: only items that have an `ItemStock` in the **active location**, joined as `PantryItem[]` (via `getStockedItems`). Items not stocked in the active location are absent. Switching the active location re-scopes the result (the active id is in the query key `['items', 'stocked', { locationId }]`). All seven pantry views (`PantryListView` + the three group + three detail views) use this instead of `useItems`. Cloud mode falls back to the full cloud item list (ItemStock has no cloud backend yet). Contrast with `useItems()`, which returns **every** global `Item` joined with active-location stock (zeroed when not stocked) — used by the Add combobox catalog, cooking (to mark unavailable items), and shopping.
- `useAddItemToLocation()` (`src/hooks/useItems.ts`) - Mutation that stocks an existing global item in a location via copy-on-add (`addItemToLocation` — inherits `targetQuantity`/`refillThreshold`/`dueDate`, with packed/unpacked → 0; there is no configuration left on a row to copy since v16). Takes `{ itemId, locationId? }` — `locationId` defaults to the active location, and the Stock-tab pager passes the location of the page being viewed. No-op-safe: returns the existing row without resetting quantities if the item is already stocked there. Invalidates `['items']` + `['itemStocks']`. **Local-mode only — throws in cloud mode** (cloud has no locations or `ItemStock`, so a stray call would write an orphan local row and report false success). Used by the pantry Add combobox's select-existing path and the Stock tab's "Add to location" CTA.
- `useRemoveItemFromLocation()` (`src/hooks/useItems.ts`) - Mutation that un-stocks an item from a location (`removeItemFromLocation`), cascading that location's inventory logs and its entries in that location's carts. Takes `{ itemId, locationId? }` — `locationId` defaults to the active location, and the Stock-tab pager passes the location of the page being viewed. The global `Item` survives: an item removed from its last location becomes an **orphan**, hidden from the pantry (`getStockedItems` filters on `ItemStock`) but still in the Add combobox catalog (`getAllItems`) and re-addable via `useAddItemToLocation`. Invalidates every family the cascade touches — `['items']` (pantry list, item reads, the item's logs), `['itemStocks']`, `['cart']`, `['sort']`, `['inventoryLogs']` and `['cartItems']` (the two per-item counts) — so removing from the **active** location leaves the UI consistent without a reload. **Local-mode only — throws in cloud mode**; it is destructive and irreversible, so it refuses loudly rather than silently deleting local rows the cloud UI never reads. Components must still gate their own UI on `mode === 'local'` (the `NewItemDialog` pattern) — the hook guard is a safety net, not a substitute.
- `useUpdateItem()` (`src/hooks/useItems.ts`) - Takes `{ id, updates, locationId? }`. In local mode the five per-location state fields (`packedQuantity`, `unpackedQuantity`, `targetQuantity`, `refillThreshold`, `dueDate`) are split into `locationId`'s `ItemStock` (defaulting to the active location) and everything else — identity **and** the eight global stock settings — is written to the `Item`, applying to every location at once; the Stock-tab pager passes the location of the page being viewed. Cloud mode ignores `locationId` — a cloud `Item` carries its stock inline. Invalidates `['items']`, the per-tag/vendor counts, and `['itemStocks']` (it writes an `ItemStock` row, which the Stock pager reads back).
- `useApplyUnitSwitch()` (`src/hooks/useItems.ts`) - Commits a unit switch as ONE Dexie transaction (`applyUnitSwitchBatch`): the `Item`'s global stock configuration, the converted quantities for **every** location, and the rewritten `defaultAmount` of every affected recipe. Takes `{ itemId, updates, locationId?, stockConversions, recipeUpdates }` — all arithmetic is the caller's, since the transaction may not await anything of its own. Invalidates every family it touched in one pass: `['items']` (+ `['items', id]` and the per-tag/vendor counts), `['itemStocks']`, `['recipes']` (+ `['recipes','itemCount']`) — a missed one shows up as a stale screen after a *successful* save, never as an error. **Local-mode only — throws in cloud mode**, which keeps the Info tab's sequential path (Apollo has no client-side transaction to borrow). Used exclusively by the Info tab's unit-switch confirmation.
- `useInventoryLogCountByItem(itemId, locationId?)` / `useCartItemCountByItem(itemId, locationId?)` (`src/hooks/useItems.ts`) - Per-item counts of the two families `removeItemFromLocation` cascades. Passing `locationId` scopes each count to exactly the rows a removal from that location would delete (logs with an absent `locationId` read as the default location; cart entries match on the parsed cart id); omitting it counts every location. The location is part of the query key, so the two scopes never share a cache entry. The Stock tab's remove confirmation uses the scoped form — an item-global count would over-report what is being deleted.
- `useItemStock(itemId, locationId?)` / `useItemStocks(itemId)` / `useItemStocksForLocation(locationId?)` (`src/hooks/useItemStocks.ts`) - Raw `ItemStock` row reads. `useItemStock` returns the single (item × location) stock (defaults to the active location); `useItemStocks` returns every location's stock for an item; `useItemStocksForLocation` returns all stocks in a location. **Local-first only** — `ItemStock` has no cloud GraphQL backend yet (cloud TODO). The joined stock that pages consume comes via `useItems`/`useItem`; these expose the underlying rows for callers that need them (e.g. the Stock-tab pager in a later phase).

**Shelf:**
- `useShelvesQuery()` (`src/hooks/useShelves.ts`) - Returns all shelves. Dual-mode: local uses TanStack Query + Dexie; cloud uses `useGetShelvesQuery` (Apollo).
- `useShelfQuery(id)` (`src/hooks/useShelves.ts`) - Returns a single shelf by ID. Dual-mode.
- `useCreateShelfMutation()` / `useUpdateShelfMutation()` / `useDeleteShelfMutation()` (`src/hooks/useShelves.ts`) - CRUD mutations. Dual-mode.
- `useReorderShelvesMutation()` / `useReorderShelfItemsMutation()` (`src/hooks/useShelves.ts`) - Reorder mutations. Dual-mode.
- Note: `FilterConfig` only holds `tagIds`, `vendorIds`, `recipeIds`. Sort is handled globally via `useSortFilter`.
