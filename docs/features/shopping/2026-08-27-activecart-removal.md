# Cleanup: remove the dead `activeCart` / `useActiveCart` path

**Date:** 2026-08-27
**Area:** `apps/web` shopping hooks + `apps/server` cart schema/resolver
**Issue:** [#265](https://github.com/ETBlue/player1inventory/issues/265)

## What was removed and why

The single "active cart" architecture was superseded by permanent 1:1 vendor
carts in `bb849853` (2026-06-10), but `activeCart` / `useActiveCart()` was left
behind. It had become **dead as a data source yet still live on the wire**: an
`ActiveCart` POST went out on every cloud checkout and cancel, and nothing ever
read the result.

Spotted in the browser network tab while verifying
[#264](https://github.com/ETBlue/player1inventory/pull/264).

`useActiveCart()` had zero production callers — only its own definition, its own
tests, and one stale cross-reference comment. Both shopping routes already used
the vendor-cart hooks (`useVendorCart` on `/shopping/$vendorId`,
`useAllActiveCarts` on `/shopping`).

### Why the query was still on the wire

`refetchQueries`. Four entries listed `ActiveCartDocument` in the **object form**
`{ query: DOCUMENT }`, which Apollo executes unconditionally — unlike a string
entry (`'VendorCart'`), which refetches only queries that are *currently active*.
The object form does not care whether anything is watching.

All four were redundant: every one of those same arrays already contained
`'VendorCart'` and `{ query: AllCartsDocument }`, which cover the no-vendor cart
through hooks that actually render. Removing them changed no behaviour.

### The server side was a strict special case

`activeCart` was `vendorCart(vendorId: null)` under another name — same
`requireAuth`, same `findUnique({ where: { id: 'no-vendor' } })`, same
create-on-miss, same return shape. The local (Dexie) branch was equally
redundant: it called `getCart(null, activeLocationId)`, the same call
`useVendorCart(null)` makes, differing only by a second TanStack cache key.

### It was left behind, not deliberately kept

`2026-06-05-vendor-carts-design.md:165` already declared it
*"Deprecated → replaced by `useVendorCart(vendorId)`"*, but Phase F of
`2026-06-09-permanent-vendor-carts-plan.md` enumerated the cloud cleanup by name
(`allActiveCarts` → `allCarts`, `getOrCreateActiveCart`) and simply omitted
`activeCart`. No commit anywhere cites backward compatibility or a migration
window.

## ⚠️ Deployment ordering

The commits are ordered **client-first, server-last**, deliberately.

A deployed old bundle firing `ActiveCart` via checkout's `refetchQueries` against
a server that no longer declares the field gets `GRAPHQL_VALIDATION_FAILED`.
Because `refetchQueries` rejections surface through `useCheckout`'s error path
(`options?.onError?.(err)`), **checkout would appear to fail to the user even
though the mutation succeeded and the cart was cleared.**

Commit 1 stands alone safely: it drops only the four redundant `refetchQueries`
entries, so clients stop firing the query while the server still answers it.
Residual risk after merge is limited to a browser tab holding a pre-merge bundle
during the window between the web and server deploys.

**Server (commit 3)**

- `schema/cart.graphql` — the `activeCart: Cart!` field

directories are gitignored, so they appear in no commit.

`useAllActiveCarts` / `allCarts` are a **different, live** concept — the
vendor-cart list — and were untouched.

## Test coverage

No behaviour changed, so no new behaviour tests. Two existing pieces of coverage
were preserved rather than deleted:

**Client** — the two `deserializeCart` wire-format tests from #264 (ISO 8601 and
legacy epoch-millis `lastPurchasedAt`) used `useActiveCart` only as a vehicle.
They were **re-pointed at `useVendorCart`** with assertions unchanged.

**Server** — three of the four `activeCart` assertions were already duplicated
(ISO serialization across `vendorCart`/`allCarts`/`checkout` ×2/`abandonCart`;
create-on-miss and the null-on-the-wire check under `vendorCart`/`allCarts`).
One was genuinely unique — create-on-miss *under the `vendorId ?? 'no-vendor'`
fallback* — and was ported into the `vendorCart` describe as
`user gets a new no-vendor cart created if none exists`.

### Mutation check

| Mutation | Result |
|---|---|
| epoch-millis branch deleted from `parseWireDate` | re-pointed epoch-millis test **RED** (ISO test correctly stays green — it does not exercise that branch) |
| `lastPurchasedAt: parseWireDate(raw.…)` → passthrough in `deserializeCart` | **both** re-pointed tests **RED** |
| `vendorId ?? 'no-vendor'` → `vendorId ?? 'WRONG'` | ported server test **RED** — while the pre-existing `null vendorId falls back to no-vendor cart` test stays green, since its `findUnique` mock answers any where-clause. The ported test is a strictly stronger guard. |
